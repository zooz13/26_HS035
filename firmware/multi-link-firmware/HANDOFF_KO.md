# 다른 Codex를 위한 펌웨어 인계

## 현재 목표와 작업 경계

저장소는 [`team-ige-wae-andwae/new-firmware`](https://github.com/team-ige-wae-andwae/new-firmware)이며, 기존 로컬 폴더 이름은 `2x2-firmware`일 수 있습니다. ESP32-S3 / ESP-IDF 6.0.1용 **펌웨어 3.0.0**입니다. 네 보드가 A → B → C → D 순서로 송신자가 되는 `RR4`를 추가했고, 기존 `1X3`·`2X2` 명령을 유지했습니다. 수집기 구현은 이 저장소의 범위 밖이며 다른 담당자가 진행합니다.

**현재 보드는 기존 고정 TX/RX 펌웨어로 유지합니다. 지금 새 이미지를 플래시하거나 자동으로 실험을 시작하지 마세요.** 먼저 [기존 firmware 저장소](https://github.com/team-ige-wae-andwae/firmware)로 고정 1TX·3RX, 1TX·4RX 실험을 진행하고, 사용자가 순환 실험을 시작할 준비가 된 뒤 새 이미지를 설치합니다. 이 저장소에는 `1X4` 모드나 E 노드가 없습니다. 기존 실험에 RX를 추가하는 절차와 RR4 설치 절차를 혼동하지 마세요.

이전 TX가 60 Hz였던 원인은 기존 NVS `csi_ctrl/rate_hz=60`이 소스 기본값 40을 덮어쓴 것이었습니다. 새 펌웨어는 별도 `csi_node_v2`를 사용합니다. 다만 이전 교대 펌웨어의 `csi_node_v2` 설정은 유지되므로 새 기본값만 믿지 말고 설치 후 네 보드를 명시적으로 CONFIG합니다.

## 준비되었을 때 한 번 빌드된 이미지로 네 보드 설치

저장소의 같은 버전 `prebuilt/`와 `scripts/`를 함께 받습니다. 보드마다 다시 빌드할 필요가 없습니다. `prebuilt/build-info.json`의 버전/소스 정보와 `prebuilt/SHA256SUMS`를 보관하고 `flash.ps1`의 체크섬 검사를 통과시킵니다. 바이너리와 체크섬 파일을 서로 다른 버전에서 섞지 마세요. 펌웨어를 수정했을 때만 ESP-IDF 빌드가 필요합니다.

기존 보드의 플래시/NVS 백업을 보관하고, 시리얼 모니터를 닫은 뒤 저장소 루트 PowerShell에서 실행합니다. `COM3`은 예시이며 실제 연결된 보드 포트로 바꿉니다.

```powershell
python -m pip install 'esptool>=5,<6'
.\scripts\flash.ps1 -Port COM3 -DryRun
# 사용자가 새 실험으로 전환할 준비가 된 뒤:
.\scripts\flash.ps1 -Port COM3
```

설치 속도 기본값은 460800 baud, 실행 후 콘솔은 **921600 baud / 8N1**입니다. 같은 이미지를 A/B/C/D 네 보드에 설치하고 UART 설정으로만 ID를 구분합니다. 부트로더 `0x0`, 파티션 `0xa000`, 앱 `0x20000`을 기록하며 전체 플래시를 지우지 않습니다. NVS 보존은 기존 팀 펌웨어와 같은 파티션 레이아웃일 때를 전제로 합니다. `erase-flash`를 설치 절차에 임의로 추가하지 마세요.

## RR4 설정·시작·정지

각 줄은 해당 보드 한 대에만 LF로 끝내 전송합니다. 모든 보드가 같은 ID가 되지 않도록 주의합니다.

```text
NODE CONFIG A RR4 20 50
NODE CONFIG B RR4 20 50
NODE CONFIG C RR4 20 50
NODE CONFIG D RR4 20 50
```

각 보드에서 `NODE_ACK,CONFIG,OK,saved`를 확인하고 `NODE STATUS`로 고유 ID, `RR4`, `20`, `50`, `STOPPED`를 확인합니다. ACK 오류나 설정 불일치가 있으면 시작하지 말고 원인을 해결합니다. CONFIG는 NVS에 저장되며, 재부팅하면 설정을 유지하되 항상 STOPPED입니다.

1. 네 UART의 원본 로그와 수집을 먼저 시작해 초기 행도 보존합니다.
2. B/C/D에 `NODE START 1001`을 먼저 전송하고 정상 ACK와 ARMED를 확인합니다.
3. A에 마지막으로 `NODE START 1001`을 전송하고 RUNNING을 확인합니다.
4. 종료 시 A에 `NODE STOP`을 먼저 보내고, B/C/D에도 `NODE STOP`을 보냅니다. STOP은 로컬 명령이며 이미 허가된 패킷 하나가 마무리될 수 있습니다.

`1001`은 예시입니다. 실험마다 새로운 공통 session 번호(1–4294967295)를 모든 보드에 사용합니다. A가 코디네이터로 매 슬롯 GRANT를 보내며, 다른 보드는 유효한 GRANT 없이 자율 송신하지 않습니다. A를 재시작하거나 FAULT를 복구할 때도 전체 노드에 새 세션을 적용합니다. 보드가 빠져도 슬롯은 압축되지 않습니다.

## 스케줄과 수집량

| RR4 슬롯 | 센싱 TX | 센싱 RX |
| --- | --- | --- |
| 0 | A | B, C, D |
| 1 | B | A, C, D |
| 2 | C | A, B, D |
| 3 | D | A, B, C |

이 순서를 반복합니다. `RR4 20 50`은 **노드별 송신 20 Hz, 네 슬롯 순환 50 ms, 슬롯 12.5 ms**입니다. 명목 합계는 DATA 80개/초와 GRANT 80개/초, 노드별 CSI 60개/초, 전체 CSI 240개/초입니다. 물리 링크는 6개, 방향별 관측은 12개이며 각 방향은 20개/초입니다. 같은 위치의 반대 방향을 독립적인 새 공간 경로로 세거나 보정 없이 합치지 마세요.

기존 `2X2 40 5000`은 A/B ↔ C/D 그룹 교대로 물리 링크 4개·방향별 관측 8개, 전체 CSI 목표 160개/초였습니다. RR4는 같은 명목 무선 패킷 수에서 수집 기록 수가 1.5배입니다. 단순 저장·전처리 부하는 대략 이에 비례하지만, 모델 계산량은 구조에 따라 달라집니다. RR4도 수신 슬롯 세 개가 12.5 ms 간격으로 이어지므로 순간 수신 간격이 1/60초로 균일하지는 않습니다.

역할 변경 때 Wi-Fi를 재시작하거나 별도 전환 대기를 넣지 않습니다. 매 슬롯의 응답·송신 완료·보호 간격을 그대로 유지합니다. 지연된 GRANT는 다음 슬롯을 미루므로 실제 주기/주파수는 명목값보다 느려질 수 있습니다. 현재 지원하는 `(노드당 Hz, 순환 ms)` 조합은 `(5,200)`, `(8,125)`, `(10,100)`, `(20,50)`뿐입니다. 1 ms·0.5 ms 교대나 `40 25`는 현재 구현이 지원하지 않으며, 이는 모든 ESP32 장치의 물리적 한계를 측정한 결과라는 뜻은 아닙니다.

## 수집기 담당자에게 전달할 형식

UART에는 부트 로그·ACK·상태·CSI가 섞입니다. 원본 로그를 보존하고 CSI 행만 별도로 파싱합니다. 명령 처리 중에도 모든 보드 UART를 계속 읽어야 합니다. [영문 프로토콜 문서](csi_node/README.md)에 전체 상태 필드와 타이밍 규약이 있습니다.

```text
type,session,phase,slot,tx_id,rx_id,seq,rx_timestamp,rssi,channel,secondary_channel,sig_mode,mcs,bandwidth,noise_floor,first_word_invalid,csi_len,csi_b64
CSI_DATA_V2,...
```

- `seq = slot`은 전역 슬롯입니다. RR4의 같은 TX는 4씩 증가하고 `phase = slot / 4`는 순환 번호입니다. 이를 같은 TX에서 세 패킷이 누락된 것으로 세면 안 됩니다. 기존 2X2는 활성 구간에서 2씩 증가하며 비활성 구간은 의도된 공백입니다.
- 관측 키는 `session + slot + tx_id + rx_id`입니다. 여러 RX에서 같은 TX 패킷을 맞출 때는 `session + slot + tx_id`를 사용합니다. mode/rate/cycle, 보드 ID, 펌웨어 버전, 호스트 시간 기준은 세션 메타데이터로 별도 보존합니다.
- `rx_timestamp`는 각 RX의 로컬 32비트 마이크로초 시계로 약 71분마다 넘칩니다. 보드 간 공통 절대시각으로 사용하지 않습니다. 실제 수신 주파수는 같은 RX의 타임스탬프를 펼쳐 계산하고, 슬롯 기울기와 해당 TX의 패킷 주파수를 구분합니다.
- `csi_b64`는 RFC 4648 base64입니다. 엄격하게 디코딩하고 결과 길이가 `csi_len`과 같은지 검사한 뒤 signed int8로 해석합니다. 예: `AAF/gP8=` → `[0, 1, 127, -128, -1]`.
- 유효 CSI 길이는 **1–768바이트의 가변값**입니다. 384로 고정하거나 다른 길이를 조용히 버리지 마세요. 원본·길이·PHY 메타데이터를 보존하고, 서로 다른 레이아웃을 임의로 패딩/잘라서 합치지 마세요. `first_word_invalid=1`이면 원본은 보존하되 첫 4바이트는 분석에서 무효로 취급합니다.
- 기존 Gateway의 **384 I/Q 값·192 amplitude 고정 처리**는 펌웨어와 별도의 수집/분석 제약입니다. 새 포맷에 연결하기 전에 담당자가 입력 파서와 특징 추출을 따로 검토해야 합니다. 이 저장소에는 Gateway나 수집기 수정이 포함되지 않습니다.

`NODE STATUS`는 기존 `NODE_STATUS`와 `NODE_TIMING`, `NODE_TX_TIMING`에 더해 다음 진단행을 출력합니다.

```text
NODE_CSI_STATS,min_len,max_len,invalid_length_dropped
```

현재 grant/session/source/수신 마스크가 일치하는 DATA의 CSI만 집계합니다. min/max에는 거부된 0 또는 768 초과 길이도 포함되며, 관측 전에는 `0,0,0`입니다. 폐기 카운터는 0 길이·768 초과·null 버퍼를 셉니다. START 때 초기화합니다. CSI 큐 넘침은 기존 `csi_dropped`에서 따로 확인합니다. 길이 폐기·큐 넘침·호스트 파싱 오류가 모두 0이어도 무선 패킷 손실이 0이라는 뜻은 아닙니다. 32개 큐와 base64는 UART 부하를 줄일 뿐, 전파 손실을 복구하지 않습니다.

**CSI 길이가 과거 누락의 원인이었다는 인과는 확인되지 않았습니다.** 확인한 2026-10-08 저장 자료는 모두 384바이트였습니다. 기존 RX의 Wi-Fi 콜백 안에서 긴 정수열을 출력하며 대기하는 처리는 병목 가능성이었고, 새 큐·base64 출력은 이를 완화합니다. 현재 고정 TX/RX 보드에는 이 새 개선을 설치하지 않았습니다.

## 검증 경계와 후속 작업

2026-10-14 네이티브 C 프로토콜 테스트(`1 passed`), ESP-IDF 6.0.1 빌드, 버전 3.0.0 이미지·체크섬·설치 dry-run 검사를 통과했습니다. 새 RR4 버전은 **실기기 미설치·4보드 미실측**입니다. 이 검사 결과는 실제 무선 성능과 구분해야 합니다. 배포본의 빌드 정보와 최신 테스트 결과를 확인하되, 하드웨어 미검증 문구를 이전 실측 결과로 대체하지 마세요.

이전 1X3/2X2 이미지에서만 A/C 두 보드의 단방향·양방향 수신, STOP 후 송신 중단, 재부팅 STOPPED를 확인했습니다. 그 결과는 새 RR4의 4보드 검증을 대신하지 않습니다.

사용자가 순환 실험을 시작할 때는 네 보드 모두의 12개 방향별 기록, 정상 seq 간격 4, CSI 길이 분포, UART 파싱 오류, 큐/길이 폐기, GRANT 지연·보호 간격 연장, FAULT, A 정지 후 송신 중단을 확인합니다. 충분한 시간 동안 실제 링크별 수신률과 누락률을 측정하고, 원본 로그·설정·버전을 함께 남깁니다. 고정 1TX 실험 데이터와 RR4 데이터는 세션/모드별로 구분해서 비교합니다.
